## 1. Method recap

Claim units were drawn from archived Chinese-language regulatory/"about" pages supplied from the Common Crawl capture set (web.archive.org was not fetchable from the verification environment; three domains were additionally blocked live — see §5), and each unit was normalised to one triple of *brand domain × named authority × displayed identifier*, so that a page displaying six authorities yields six independently codeable units. Each unit was then run through the protocol §6 two-step check against the regulator's own register only: (i) does the claimed record exist in the official register, and (ii) is the published licence-holder's name the same as the entity named on the page — recorded separately, with scope, status and approved-domain fields captured wherever the register publishes them, and `UNVERIFIABLE-TODAY` plus a reason recorded wherever it does not. Classification is made against the **operative entity** for the domain — the entity that would actually be the client's counterparty — established under the frozen evidence ladder OE-1 (publicly posted client agreement) > OE-2 (footer trading-name sentence) > OE-3 (explicit site-operator sentence on the brand's own regulation page); where no rung resolves, the unit is coded `D-operative-indeterminate` rather than assigned by inference.

## 5. What the method established

**Does two-step verification work at scale?** Yes, with a measurable ceiling set by register design rather than by effort. All 14 units returned a determinate answer to step (i) at some level and a determinate answer to step (ii) wherever an operative entity existed — no unit had to be abandoned. Cost was concentrated in access rather than analysis: three domains blocked the page side (HTTP 403 across all corporate paths on one; a redirect loop on a Chinese path on another; HTTP 526 on a policy subdomain on a third), and web.archive.org was not fetchable from the environment, which is what drove both indeterminate operative-entity outcomes. Notably, the operative-entity rule did real work rather than being a formality: it converted claim #6 from "step (ii) not performable" (no page-side name captured) into a determinate class-B coding, and it is the sole reason #1, #7 and #14 are D rather than falsely confident A's.

**Which registers publish enough to discriminate B from C?**

*Number-level discrimination (a claimed identifier can be resolved to a named holder):*
- **FCA (UK)** — strongest. Number search, holder legal name, all current and historical trading names with effective dates, permissions by activity and client type, status with dates, register-published website and contact, Companies House number, notices section. This register alone let #2 be separated into "record exists, held by a different entity, of a category that carries no permissions, and not currently registered" — four distinct findings from one lookup.
- **ASIC (AU)** — number search, licensee name with full name history, conditions text with client types per authorisation row, status, EDR membership, authorised representatives, principal website.
- **CySEC (CY)** — licence number on the entity page, holder and former name, approved trade name, service and instrument scope, cross-border scope, plus the only genuine **approved-domain register** encountered, with a matching non-approved list.
- **FSCA (ZA)** — FSP number search, holder name, status, date authorised, category/subcategory/service-type grid, key individual. One practical defect: the register is POST-driven with **no GET-addressable permalink per FSP**, so citations cannot be reproduced by URL — the number must be re-entered on the search form.

*Name-level only (B vs C cannot be separated at number level):*
- **FSA Seychelles** — publishes name, address, trade name, contact and website, but **no licence numbers, no status, no dates, no scope** in any tab. Three units (#7, #8, #9) hit this. The trade-name and website fields are unusually useful for the operative-entity question, but a claimed SD number can be neither confirmed nor excluded. The FSA's own notices show SD numbers circulating in citation without the register naming holders.
- **FSC Mauritius (OPR)** — the hardest limit encountered: **no licence-number search field and no licence-number column anywhere**, in either the result grid or the detail view. Filters are Relevant Act, Category, Activity and Name only. Three units (#10, #11, #12) are therefore name-level at best.
- **Labuan FSA** — the money-brokers roster is eleven columns of contact data with no number, status, date, scope or website field. One unit (#13).

The practical rule this yields: **B and C are separable only where the register exposes an identifier-to-holder mapping.** In name-only registers, the achievable finding is "an entity of this name is licensed in this category," and the honest code for the number element is D — never an inference from the brand's own page or from a third-party site.

**Recurring failure modes.**
1. **Scope** (4 units, appearing under both A-adjacent and B codings): wholesale-clients-only authorisation displayed on a retail-facing page (#3); an authorisation covering arranging and acting on behalf of another, but not issuing, for the exact product class the page offers (#4); a Category I approval marked only in "Intermediary Other" with all advice columns blank (#14); and an Appointed Representative record that by construction carries no permissions of its own (#2). Scope divergence is invisible unless the register publishes per-activity client types — only FCA, ASIC, CySEC and FSCA do.
2. **Approved domain** (3 units): only CySEC operates a true approved-domain list, and in both CySEC units the observation domain was absent from it while a different domain was published for the holder (#5, #6). Other registers publish a "website" field that is not an approval statement: it matched the observation domain in #8 and #9, matched only at path level in #7, and pointed to an unrelated domain in #2 and #4. Absence from any of these fields is a register-content observation, not a finding about the domain.
3. **Identifier instrument** (5 units): the displayed string is frequently not of the same type as anything the register indexes. GB-prefixed Mauritius strings sit in a licence-number position on the page while the OPR indexes only SEC-x.x / FS-x.x licence *types* under a separate Category field (#10, #11, #12); SD- and MB- strings are simply not published by their regulators (#7, #8, #9, #13). This is the failure mode most likely to be miscoded as C by an analyst who treats "not found" as "does not exist."
4. **Authority naming** (1 unit, high salience): a national regulator named on a page whose underlying record is an Appointed Representative registration — a distinct register category from authorisation, with permissions residing on a principal's record and, here, with the registration no longer current since 08/07/2026 (#2). Naming the authority is accurate; the record's category and currency are separate published fields that the page text does not convey.
5. **Status currency** — only four of the seven registers publish status at all, so "currently registered" is an unanswerable question for units 7–13.
